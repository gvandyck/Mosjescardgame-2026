<objective>
Fix BUG-01: Quest roll threshold displays wrong tier in certain scenarios.

The bug report: "Strategy Puzzle shows 3+ instead of 2+ when player has Mental ★★★ (stat level 3)".

There are two independent code paths that produce a threshold:
- Path A: `getQuestDiceThreshold(questDef, activeMosje)` — reads `roll.thresholds[stars]` — used by the
  modal display (main.js line 541) and by `showQuestAttemptPreview` (main.js line 732/1013)
- Path B: Quest-specific requirement functions (`quest_req_strategy_puzzle`, `quest_req_quick_thinking`)
  — used to perform the actual roll

If these two paths return different values for the same input, the displayed threshold and the actual
success condition disagree. The fix approach:
1. Create regression tests that assert both paths agree for every mental quest at every stat level
2. Run the tests — if RED, the failing case reveals the exact mismatch
3. Fix the mismatch (either in quests.js threshold data, or in the requirement function array)

Strategy: test-first investigation. The tests are the executable specification.

Purpose: Player sees accurate threshold in the quest modal before rolling.
Output: tests/engine/quest-threshold.test.ts; any fix in questLogic.js or quests.js identified by the failing tests.
</objective>
