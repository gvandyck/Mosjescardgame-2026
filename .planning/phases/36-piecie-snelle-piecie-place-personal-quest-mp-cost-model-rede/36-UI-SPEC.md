# Phase 36 — UI Design Contract

> Visual and interaction contract for Phase 36: Piecie/Snelle Piecie/Place/Personal Quest MP Cost
> Model Redesign. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

**This phase is fundamentally an engine/data-model rework, not a UI phase.** It was flagged by
the plan-phase UI gate on a false-positive keyword match ("ui" inside "requires" in the phase
title). Per `36-RESEARCH.md` (Critical Finding 4) and `36-CONTEXT.md` decisions D-05/D-06/D-07,
the ONLY real UI surface in this phase's scope is:

1. **One reusable tribute-payer picker** — reused/reworked for `piecie_welloe_force` (the sole
   confirmed self-paying card today) and any additional card the COST-01/02 text audit
   confirms needs tribute (expected: 0-2 more, `snelle_blensen` is the open edge case — see
   Open Question 1 in `36-RESEARCH.md`). This is not a new component: it is a thin, parameterized
   wrapper around the existing `showOptionSelect` primitive, following the exact shape already
   proven for Welloe Force's *target* picker (`.planning/phases/12-unfinished-stubs/12-UI-SPEC.md`,
   STUB-14) — this phase repurposes that same modal family for *payer* selection instead of
   *target* selection, and adds the affordability gate D-06 requires (which STUB-14's version
   never had).
2. **The existing cost-chip** (`modalManager.js:467` — `chips.push((card.mpCost === 0 ||
   card.mpCost == null) ? 'Free' : \`${card.mpCost} MP\`)`) stays byte-for-byte unchanged. Per
   D-07/D-08, correcting the underlying `mpCost` data values is what makes this chip accurate
   again — zero code changes to the chip itself.
3. **Affordability gating** (D-06) — a state/validation contract, not a new visual: ineligible
   Mosjes are disabled in the picker list (existing `disabled` styling already defined in
   `styles/board.css:1483-1496`), and if **zero** Mosjes can afford the tribute, the action is
   blocked before the picker ever opens, using the existing `modal.showInfo(title, message)`
   blocked-action pattern (already live at `main.js:1988` for an unrelated MP-affordability
   check — same shape, reused verbatim).

No new screens, no new layouts, no new design-system elements, no new colors, no new spacing
tokens are needed. This contract exists to pin down the exact copy and exact reuse contract for
the one picker, so the planner/executor don't improvise a bespoke modal.

## Component Inventory

### 1. Tribute-Payer Picker (new reusable helper — generalizes `showMosjeSelect`)

**Purpose:** when a ruled card's text says it costs MP but does not name which Mosje pays (D-05),
show one modal listing every on-field Mosje the player controls; the player picks which one pays.
Reuses `showOptionSelect` under the hood, following the exact shape of the existing
`showMosjeSelect` quest-cost picker (`modalManager.js:733-765`) — do not build a new bespoke modal.

**Recommended implementation shape** (planner/executor discretion on exact function name/file
location, per CLAUDE.md's "build once, reuse everywhere" rule — this is the contract for its
behavior and copy, not a mandated function signature):

```js
// Generalizes showMosjeSelect's hardcoded `questCost = 20` into a parameter, OR adds a
// sibling function sharing the identical body shape (either satisfies "build once, reuse").
function showTributePayerSelect({ title, prompt, mosjeSlots, amount }) {
  const options = mosjeSlots.map(slot => {
    const canAfford = slot.mp >= amount;
    return {
      id: String(slot.slotIndex),
      label: slot.name,
      metaLabel: `<span style="color: ${canAfford ? '#4ade80' : '#ef4444'};">${slot.mp} MP</span>`,
      disabled: !canAfford,
    };
  });
  return showOptionSelect({ title, prompt, options, allowCancel: false });
  // Resolves with the chosen slotIndex string, or null only if the caller allows cancel
  // (this phase's cards do not — D-06 requires the action itself to be blocked upstream
  // if zero Mosjes qualify, not a cancel path inside the picker).
}
```

**State contract:**
- `mosjeSlots` = every on-field Mosje slot for the acting player (mirrors `showMosjeSelect`'s
  existing `mosjeSlots` shape: `{ slotIndex, name, mp, disabled }`).
- `amount` = the tribute cost in MP, read from the card's (corrected) `mpCost` value.
- Every option where `mp < amount` renders `disabled` (existing `.modal-mosje-select-btn--disabled`
  styling — no new CSS).
- **Pre-check before opening the modal at all:** if every Mosje slot has `mp < amount`, do NOT
  open this picker — show the blocked-action dialog instead (see Component 2) and do not charge
  anything, do not activate the card.
- On resolution: charge `amount` MP from the chosen Mosje via the existing `applyDamage(mosje,
  amount)` helper (`piecieEffects.js:29-42`) — already proven safe for this once the affordability
  pre-check guarantees `mp >= amount`, so `applyDamage`'s defeat-at-0 path can never fire from a
  tribute payment (closes Common Pitfall 4 / Critical Finding 4 in `36-RESEARCH.md`).

**Exact call for Welloe Force's rework** (the one confirmed consumer):
```js
const payerSlotIndex = await modal.showTributePayerSelect({
  title: 'Welloe Force — Pay Tribute',
  prompt: 'Choose which Mosje pays the 40 MP tribute to activate Welloe Force.',
  mosjeSlots: activeMosjeSlots,       // all of the acting player's on-field Mosjes
  amount: 40,
});
```

### 2. Blocked-Action Dialog (existing `showInfo` — reused verbatim, zero changes)

**Purpose:** when D-06's affordability gate finds zero eligible payers, the card cannot be played
or activated at all. Reuses the existing `modal.showInfo(title, message)` function
(`modalManager.js:47-59`), already live for an unrelated MP-affordability block (`main.js:1988`,
Elimination Strike ability) — same pattern, same copy shape, no code change to `showInfo` itself.

**Exact call:**
```js
modal.showInfo(
  'Cannot Activate',
  `Not enough MP — Welloe Force requires 40 MP tribute from one Mosje (none of yours can afford it).`
);
return state; // no charge, no activation, card stays in hand/on field unchanged
```

Primary CTA for this phase: not applicable — there is no new primary call-to-action button; the
picker's options ARE the interaction (identical to the existing `showMosjeSelect` quest picker).
