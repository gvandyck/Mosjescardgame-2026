Key facts from research (confirmed — do not re-read source files for these):

1. modalManager.js `showDiceRoll` (line 71). The dice result is computed inside `doRoll()`:
   ```javascript
   const rawRoll = Math.floor(Math.random() * 6) + 1;
   const result = rawRoll + diceBonus;          // result = effective roll shown to player
   const didSucceed = result >= threshold;
   ```
   `threshold` is the parameter of `showDiceRoll` — it is in scope inside `doRoll` (closure).

   The "Continue →" button click handler at line ~134 calls:
   ```javascript
   container.querySelector('#modal-done')?.addEventListener('click', () => {
     close();
     onResolved(didSucceed);
   });
   ```
   Change to: `onResolved(didSucceed, { roll: result, threshold });`
   Both `result` and `threshold` are in scope at that point.

2. The no-container stub at line 17:
   ```javascript
   showDiceRoll: (_info, _threshold, onResolved) => onResolved(false),
   ```
   Change to: `onResolved(false, { roll: 0, threshold: _threshold })`
   This keeps the stub safe for test environments.

3. main.js — two `showDiceRoll` call sites, both need their callback signatures updated:

   Site A (general quest, line ~1039):
   ```javascript
   modal.showDiceRoll(questDef, threshold, (didSucceed) => {
     ...
     const mpDelta = didSucceed ? questDef.successMP : questDef.failMP;
     const sign = mpDelta >= 0 ? '+' : '';
     log.add(didSucceed ? 'gain' : 'loss',
       `${questDef.name}: ${didSucceed ? 'Success' : 'Failed'} → ${sign}${mpDelta} MP`
     );
     logStateOutcome(...);
   ```

   Change callback signature to `(didSucceed, rollInfo)` and replace the log.add line:
   ```javascript
   log.add(didSucceed ? 'gain' : 'loss',
     `${questDef.name}: rolled ${rollInfo.roll}, needed ${rollInfo.threshold}+ → ${didSucceed ? 'Success' : 'Failed'} (${sign}${mpDelta} MP)`
   );
   ```

   Site B (personal/Mosje-specific quest, line ~1780):
   Same pattern — change callback to `(didSucceed, rollInfo)` and enrich the log.add if present,
   or add an equivalent one if absent.

4. The fallback no-roll-info guard: if rollInfo is undefined (shouldn't happen with the stub change
   but belt-and-suspenders), default gracefully:
   ```javascript
   const rollLabel = rollInfo ? `rolled ${rollInfo.roll}, needed ${rollInfo.threshold}+ → ` : '';
   log.add(..., `${questDef.name}: ${rollLabel}${didSucceed ? 'Success' : 'Failed'} (${sign}${mpDelta} MP)`);
   ```

5. Important: `threshold` is a local variable in `runGeneralQuestDiceRoll` and in the personal
   quest handler — it is in scope at the call site. Using `rollInfo.threshold` (from the modal)
   is preferred since it matches exactly what was displayed to the player.
