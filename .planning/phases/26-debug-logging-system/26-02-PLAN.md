3. The fix: Change `logStateOutcome` to identify level-change lines and emit them as 'level' type.

   Approach — change `logStateOutcome` (NOT `summarizeStateOutcome`) to do a targeted pattern
   check on each line before calling log.add:

   ```javascript
   function logStateOutcome(log, beforeState, afterState, actorId, label = 'Action') {
     const lines = summarizeStateOutcome(beforeState, afterState, actorId);
     if (!lines.length) {
       log.add('info', `${label}: no visible stat changes.`);
       return;
     }
     log.add('info', `${label}:`);
     for (const line of lines.slice(0, 6)) {
       // Level-up lines generated by summarizeStateOutcome match "level N -> N"
       const isLevelUp = /level \d+ -> \d+/i.test(line);
       log.add(isLevelUp ? 'level' : 'info', `- ${line}`);
     }
   }
   ```

   This is the minimal change: one regex check per line in the existing loop.
   `summarizeStateOutcome` remains pure (returns strings, no log reference) — follows the
   existing architecture.

4. The 'level' log type is already defined in logRenderer.js (confirmed by research):
