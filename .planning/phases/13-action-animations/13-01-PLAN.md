<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser DOM | Animation selectors operate on rendered elements and may fail to find a node; failure must be a no-op. |
| Game state | Animation code receives before/after snapshots but must not mutate rules state. |
| Online sync | Animation timing must not change when `pushState()` happens. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01-01 | Denial of Service | animation timers | mitigate | Keep timers short, use animationend cleanup, no recursive animation loops. |
| T-13-01-02 | Tampering | gameState from UI helper | mitigate | `actionAnimations.js` reads only; no writes to state objects. |
| T-13-01-03 | Information Disclosure | opponent face-down cards | mitigate | Face-down selectors must not expose hidden card names in DOM text; `data-card-id` on opponent face-down placeholders should be omitted or set to `face-down`. |
| T-13-01-04 | Spoofing | wrong card animated after duplicate card IDs | mitigate | Prefer player ID + zone + slot index over card ID alone. |
| T-13-01-05 | Denial of Service | reduced-motion users | mitigate | `prefersReducedMotion()` short-circuits JS animations and CSS disables motion. |
</threat_model>
