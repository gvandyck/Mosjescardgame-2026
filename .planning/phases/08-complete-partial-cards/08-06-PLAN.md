<objective>
Audit all quests marked `partial` in card-reference.md against the live implementation in
`src/data/quests.js` and the quest resolver (`src/abilities/questLogic.js` or equivalent).

For each partial quest:
1. Determine whether it is ACTUALLY broken in the browser layer (wrong outcome, crash, no effect)
   OR is just marked partial because of a simplification note from an earlier phase.
2. If the quest resolves correctly (roll fires, success/failure awards correct MP), upgrade it to `implemented`.
3. If it has a genuine gap (OR-condition simplified, interactive pick defaulted), add a `// DEFERRED:`
   comment in quests.js and update card-reference.md with a specific deferred note.

Purpose: Satisfy CARD-COMP-QUEST without introducing a new UI-blocking primitive. Quests that
work correctly under their current simplified model are fully implemented — the simplification
itself was an approved Phase 5 decision. Only genuine runtime gaps should remain partial.

Output: Updated card-reference.md quest section + DEFERRED comments in quests.js where applicable.
</objective>
