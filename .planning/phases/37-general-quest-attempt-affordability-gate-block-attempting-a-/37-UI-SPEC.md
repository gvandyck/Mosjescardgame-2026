# Phase 37 — UI Design Contract

> Visual and interaction contract for Phase 37: General Quest Attempt Affordability Gate.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

**This phase is an engine/UI-behavior bugfix, not a new-visual-design phase.** It reuses an
existing, already-contracted affordability pattern verbatim. No new screens, colors, tokens,
components, spacing, or typography are introduced.

Per `37-CONTEXT.md` (D-02, D-04, D-05, D-06), the ONLY UI surface is:

**Apply the existing `showMosjeSelect` green/red disabled-affordability convention to the
single-Mosje General-Quest attempt path** so the player cannot *start* a Quest attempt with a
Mosje that can't afford the flat 20 MP fee (which would drive it below 0 and, at Level 0,
self-destruct it — the exact Michelle knockout from the Phase 36 UAT).

The convention already exists and is already contracted:

- `showMosjeSelect` (`src/ui/modalManager.js:737-769`) ALREADY disables unaffordable Mosjes for
  quest attempts: `disabled: mosjeSlot.disabled || (isQuestAttempt && mp < 20)`, with a green
  (`#4ade80`, affordable) / red (`#ef4444`, unaffordable) MP label via its `getMpLabel` helper.
  This is the exact green/red affordability convention this phase applies.
- Phase 36's UI-SPEC (`36-UI-SPEC.md`) already contracted this same disabled-affordability
  behavior (green/red MP, disabled option, gold hover on enabled) for the Welloe Force tribute
  picker. This phase BUILDS ON that convention rather than re-deriving it — it applies the
  identical `mp >= 20` clamp to the General-Quest attempt trigger.

**What already works (D-04, D-05, confirmed live) and must NOT regress:**
- The multi-Mosje quest picker (2+ Mosjes) already routes through `showMosjeSelect` and disables
  unaffordable Mosjes (`main.js:1526`, `main.js:2701`). Done.
- Personal Quests already gate even single-Mosje, because `showMosjeSelect` always shows its
  modal regardless of count (`modalManager.js:734`) and the personal path always routes through
  it (`main.js:2701`). Verify + regression-test; no new gate code expected.

**The actual gap (D-06):** the General-Quest **single-Mosje** path. When exactly one active
Mosje exists, `main.js:1525-1528` skips the picker (`if (gqSlots.length > 1) showMosjeSelect
else showQuestPreviewThenRoll(...)`) and calls `showQuestPreviewThenRoll` directly, which charges
20 MP at `main.js:1511` with no affordability check. A prior `showConfirm` ("Pay 20 MP to attempt
this quest?") gates *intent* but not *affordability* — clicking Yes with a 10 MP Mosje still
self-destructs it. The gate must cover this one path.

The mechanism (extend `getGeneralQuestBlockReason` with an affordability reason vs. always
routing the single-Mosje case through `showMosjeSelect` too vs. a button-level disable) is the
planner's/executor's choice per D-02's Claude's Discretion. This contract pins the *behavior,
convention, and copy* only — not the wiring. Whichever mechanism is chosen must present the
disabled/blocked state to the player *before* any 20 MP is charged (a preventive disabled state,
not a post-charge dialog — D-02).

## Component Inventory

**No new components.** This phase reuses existing primitives only.

### 1. `showMosjeSelect` quest picker (existing — reused, zero visual change)

**Purpose:** the affordability-gate convention this phase applies. Already disables Mosjes with
`mp < 20` for quest attempts and color-codes the MP label green/red. If the chosen mechanism is
"always route the single-Mosje General-Quest path through `showMosjeSelect` too," this component
is reused verbatim — a single-Mosje list where the sole option renders disabled/greyed with a red
MP label when unaffordable is a valid, already-contracted presentation of D-02's "greyed-out
attempt control." No code change to the component's rendering.

**State contract (unchanged from existing):**
- `mosjeSlots` = `{ slotIndex, name, mp, disabled }` for each on-field Mosje.
- `isQuestAttempt` (via `questDef`) = true → each option gets `disabled: mp < 20` and a green/red
  MP `metaLabel`.
- Affordability threshold: `mp >= 20` (D-03) — a Mosje at exactly 20 MP is enabled (pays to
  exactly 0, survives per `phase0-rulings.md:126`); 19 or below is disabled.

### 2. Blocked-action / disabled-trigger state (existing patterns — reused)

**Purpose:** prevent the 20 MP charge before it happens on the single-Mosje General-Quest path.
Depending on the planner's chosen mechanism, this is one of:
- The disabled option inside `showMosjeSelect` (Component 1) — player sees the greyed Mosje and
  cannot select it; or
- An affordability reason added to `getGeneralQuestBlockReason` (`questLogic.js:148`, the natural
  home alongside the existing `negative-mp` reason) that disables the General-Quest attempt
  trigger upstream so the player never reaches the charge; or
- A pre-charge `showInfo('Cannot Attempt', ...)` block using the existing dialog shape
  (`modalManager.js`, live at `main.js` for other MP-affordability blocks).

D-02 prefers a *visible disabled control* over a post-click error dialog. Any mechanism chosen
must reuse an existing primitive — no new dialog component.

## Copywriting Contract

Reuses existing quest-picker copy where the picker path is used; only the disabled/blocked
affordability messaging is specified here. Exact tooltip/label wording is Claude's Discretion per
D-02 — these are the recommended defaults.

| Element | Copy |
|---------|------|
| Quest picker title (existing, unchanged) | `Choose Mosje for Quest` |
| Quest picker prompt (existing, unchanged) | `Select Mosje to attempt quest (costs 20 MP).` |
| MP meta label — affordable (existing) | `{mp} MP` in green (`#4ade80`) |
| MP meta label — unaffordable (existing) | `{mp} MP` in red (`#ef4444`) |
| Disabled-trigger tooltip/label (recommended default) | `Needs 20 MP to attempt` |
| Blocked-action title (only if a dialog path is chosen) | `Cannot Attempt` |
| Blocked-action body (only if a dialog path is chosen) | `Not enough MP — attempting a Quest costs 20 MP, and {Mosje name} has only {mp} MP.` |
| Empty state | Not applicable — a General Quest can only be attempted when at least one active Mosje is on the field; the "no Mosje" case is already handled by `getGeneralQuestBlockReason`'s `no-active-mosje` reason. |
| Destructive confirmation | Not applicable — the 20 MP fee is a direct cost gate, not a destructive/irreversible action. The gate's whole purpose is to PREVENT the accidental self-destruct, so no confirm step is added. |

Primary CTA for this phase: not applicable — no new call-to-action. The interaction is a
preventive disabled state on the existing attempt trigger / picker option.

## Interaction States

| State | Visual | Notes |
|-------|--------|-------|
| Affordable Mosje (`mp >= 20`) | Enabled attempt trigger / selectable picker option, green `{mp} MP` label | Existing `.modal-mosje-select-btn` + `#4ade80` — unchanged |
| Affordable option (hover) | Gold border + glow (`box-shadow: 0 0 14px rgba(232,185,79,0.2)`) | Existing `:hover:not(:disabled)` rule — unchanged |
| Unaffordable Mosje (`mp < 20`) | Disabled/greyed trigger or picker option: ~50% opacity, `not-allowed` cursor, red `{mp} MP` label, no hover effect | Existing `.modal-mosje-select-btn--disabled` + `#ef4444` — the D-02 gate applied to the single-Mosje path |
| Single-Mosje General Quest, sole Mosje unaffordable | Attempt cannot proceed; 20 MP is never charged; Mosje never driven below 0 | THE gap this phase closes (D-06). Presentation via whichever existing primitive the planner selects |
| Multi-Mosje picker (2+ Mosjes) | Unchanged — already gates correctly | D-04 — must NOT regress |
| Personal Quest picker | Unchanged — already gates correctly even single-Mosje | D-05 — verify + regression-test, must NOT regress |
