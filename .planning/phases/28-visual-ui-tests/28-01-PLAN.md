# Phase 28 — Plan 01: Visual UI Tests (10 Playwright Tests)

## Goal
Add 10 targeted Playwright tests in `tests/ui/` that cover the most historically buggy and mechanically complex areas of the game. Every test must assert MP before, during, and after an effect/ability/quest resolves — making regressions immediately visible in the browser.

## Selection rationale
Tests chosen from:
- Phase 9 bug list (BUG-01 to BUG-05) — all had real regressions
- Phase 27 VERIFICATION.md human_needed backlog (4 items, all now automatable via Playwright)
- Phase 24 VERIFICATION.md human_needed backlog (interrupt modal — most complex UI flow)
- Most complex engine functions: `resolveQuest`, `endTurn` sweep, `effect_leipe_swap`, `loseMP` status-effect chain, `persistUntilEndOfTurn` lifecycle

## Context

### Shared test helpers (already in `tests/ui/smoke.spec.js`)
```js
seedOfflineSession(page, deckId)  // blocks Firebase, seeds sessionStorage
waitForBoard(page)                 // waits for turn label + .mosje-card--owned
readOwnedMosjes(page)              // [{ name, mp }] via page.evaluate
readLog(page)                      // ['log row text', ...] via page.evaluate
readHand(page)                     // [{ cardId, cardType, name }] via page.evaluate
ss(page, name)                     // screenshot to tests/ui/screenshots/
```

All 10 new tests go in `tests/ui/mechanics.spec.js`. They must:
- Import helpers from `./helpers.js` (extract shared code from smoke.spec.js into this file)
- Use `ARTISTIC_RHYTHM` deck (has Chris + Youri) or `PHYSICAL_FORCE` (has Not Today!, Leipe Swap) as needed
- Assert **MP before the action**, **MP during/after the action**, and confirm the **log contains evidence**

## Task 2 — Test: Dubbele Dosis stays on field until end of turn (BUG-02)

**Background:** BUG-02 was that Dubbele Dosis discarded immediately on activation. Fixed in Phase 9. This test prevents regression.

**Mechanic:** `piecie_dubbele_dosis` has `persistUntilEndOfTurn: true`. Playing it should leave it in a piecie slot until the human clicks End Turn.

**Setup:** Use `PHYSICAL_FORCE` deck (contains Dubbele Dosis). Force it into hand via `addInitScript` if needed, or wait for it naturally.

**Assertions:**
1. MP before: record `readOwnedMosjes(page)` MP on turn start
2. Play Dubbele Dosis from hand (click play btn on `[data-card-id="piecie_dubbele_dosis"]`)
3. MP during: Dubbele Dosis gives +20 MP — assert the Mosje's MP increased by exactly 20
4. Assert `piecie_dubbele_dosis` is still in a piecie slot (`.piecie-slot[data-card-id="piecie_dubbele_dosis"]` exists, count > 0)
5. Click End Turn, wait for bot to finish
6. MP after: assert the Mosje's MP is still >= the value it had after the +20 gain (Dubbele Dosis gone, MP retained)
7. Assert Dubbele Dosis is NO LONGER in a piecie slot after the turn ends (moved to graveyard)
8. Log must contain `Dubbele Dosis` and a `+20` or `+MP` entry

**File:** `tests/ui/mechanics.spec.js`

## Task 3 — Test: Leipe Swap reverts MP at end of turn (Phase 20)

**Background:** Leipe Swap swaps your Mosje's MP with an opponent's, then reverts at end of turn. Banked levels from borrowed progress stick. This is the trickiest lifecycle in the engine.

**Mechanic:** `effect_leipe_swap` writes `state._leipeSwap`; `endTurn` reads it and swaps back.

**Setup:** Use `PHYSICAL_FORCE` deck which contains `piecie_leipe_swap`. Force both Gandoe and opponent Mosje to be on field with different MP values (set via `addInitScript` to override `mosjes:offline` and inject `_testMPOverrides` if engine supports, or just play naturally and read initial values).

**Assertions:**
1. MP before: record player Mosje MP and opponent Mosje MP via `page.evaluate` reading both `.mosje-card--owned` and `.mosje-card--opponent` `.mosje-mp-header`
2. Play Leipe Swap (select own slot + opponent slot in the modal)
3. MP during: assert own MP is now what opponent had, and opponent MP is now what player had (the swap happened)
4. Click End Turn, wait for bot to finish
5. MP after: assert own Mosje MP reverted back to its pre-swap value (±any gains from trickle/bot actions)
6. Log must contain `Leipe Swap` entry

**File:** `tests/ui/mechanics.spec.js`

## Task 4 — Test: Quest success grants MP and log shows threshold vs roll (BUG-01, Phase 26)

**Background:** BUG-01 was wrong threshold display. Phase 26 added dice roll logging. This test checks both: correct threshold shown AND correct MP awarded on success.

**Mechanic:** Click General Quest, pick a quest, observe the dice roll modal, confirm success gives MP.

**Setup:** Any deck. Use `PHYSICAL_FORCE` (Gandoe has physical traits, many quests use physical).

**Assertions:**
1. MP before: record player Mosje MP
2. Click `#btn-general-quest`
3. A quest selection modal appears — select the first available quest
4. A dice roll modal appears — assert it shows a threshold number (e.g. `needed: N`) via the modal text
5. Intercept or observe the result: if roll >= threshold → success; if roll < → fail
6. MP after success: assert MP increased by at least `successMP` (check quest def or just assert > before MP)
7. MP after fail: assert MP decreased (or stayed same if 0 floor) — never goes below 0
8. Log must contain `rolled` and `needed` and either `Success` or `Failed` text (wired in Phase 26)

**File:** `tests/ui/mechanics.spec.js`

## Task 5 — Test: Quest fail MP never goes below 0 (BUG-03 pattern, Senor West floor)

**Background:** BUG-03 was Senor West's wrong-guess penalty bypassing the MP floor. The general engine floor is in `loseMP`. This test verifies the floor holds for quest failure too.

**Mechanic:** Attempt a quest when Mosje MP is 0 (or near 0). Confirm MP does not go negative.

**Setup:** Use `addInitScript` to seed Mosje with 0 MP or use a quest with high fail penalty after MP is drained. Simplest approach: wait until a Mosje has low MP naturally, then attempt a quest.

**Assertions:**
1. MP before: assert Mosje MP is >= 0
2. Attempt general quest, observe result
3. MP after: assert Mosje MP is >= 0 regardless of success/fail
4. If fail: assert MP is exactly 0 (not negative)
5. Log confirms fail and MP change

**File:** `tests/ui/mechanics.spec.js`

## Task 6 — Test: Youri ability — single face-down Piecie auto-activates (Phase 27 human backlog #1)

**Background:** Phase 27 VERIFICATION.md listed this as human_needed. Now automatable via Playwright.

**Mechanic:** Youri Speed Activate costs 20 MP, activates a face-down piecie on field, draws 1 card. With a single face-down piecie, no slot-picker modal appears — it auto-activates.

**Setup:** Use `ARTISTIC_RHYTHM` deck (contains Youri). Play Youri into active slot. Play one Piecie face-down (don't end turn — it stays face-down for one turn). Then use Youri's ability.

**Assertions:**
1. MP before: record Youri slot MP (must be >= 20)
2. Confirm exactly 1 face-down piecie is on field (`.piecie-slot.face-down` or `[data-face-down="true"]`)
3. Click Youri's ability button
4. Assert NO slot-picker modal appeared (`.modal-overlay` not visible within 500ms)
5. MP during/after: assert Youri MP decreased by exactly 20
6. Assert the face-down piecie slot is now active (no longer face-down)
7. Hand size must have grown by 1 (a card was drawn)
8. `youriAbilityUses` incremented — confirm via `page.evaluate(() => window.__gameState?.players?.player_1?.youriAbilityUses)` if exposed, or just check that the button is still enabled for 2 more uses

**File:** `tests/ui/mechanics.spec.js`

## Task 7 — Test: Youri ability — 3-use cap enforced (Phase 27 human backlog #4)

**Background:** After 3 uses, Youri's ability button should show an error and deduct no MP.

**Mechanic:** `youriAbilityUses` is tracked per-game. At 3, the ability is blocked.

**Setup:** Use `addInitScript` to pre-set `youriAbilityUses: 3` in the offline session's game state, OR play 3 actual uses. The `addInitScript` approach is faster but requires the engine to read `youriAbilityUses` from the session — check if there's an override path. If not, play 3 turns with a face-down Piecie each time.

**Assertions:**
1. Use Youri's ability 3 times (or start with counter at 3)
2. On the 4th attempt: click ability button
3. An info modal must appear with "already been used 3 times" in its text
4. MP before and after the 4th attempt must be identical (no cost deducted)
5. Log must NOT contain a 4th `Youri` ability entry

**File:** `tests/ui/mechanics.spec.js`

## Task 8 — Test: Not Today! interrupt fires on bot elimination (Phase 24 human backlog #1)

**Background:** The interrupt modal must fire when the bot would eliminate the human Mosje. Phase 24 implemented this; it was listed as human_needed.

**Mechanic:** `showDamageInterruptModal` fires before a bot step that would eliminate or deal >= 30 MP damage to the human Mosje. Not Today! (`snelle_negate_elimination`) should be an option.

**Setup:** Use `PHYSICAL_FORCE` deck (contains Not Today!). Drive the human Mosje to low MP so the bot's next quest/attack eliminates it. Can be forced via `addInitScript` setting Mosje MP to 5.

**Assertions:**
1. MP before: record human Mosje MP (should be <= 5 after setup)
2. Click End Turn
3. Before bot resolves, a "Damage Interrupt" modal appears — assert it is visible
4. Assert "Not Today!" is an option in the modal
5. Click "Not Today!"
6. Assert the Mosje is still alive (not in graveyard) — `.mosje-card--owned` still present and not `.is-defeated`
7. Assert Mosje MP is exactly 5 (restored to 5 by Not Today! effect)
8. Log must contain `Not Today!` and the Mosje name

**File:** `tests/ui/mechanics.spec.js`

## Task 10 — Test: Two quests per turn cap is enforced (Phase 26 context)

**Background:** The game allows 0/2 quests per turn (shown in turn label as `0/2 quests used`). A third quest attempt in the same turn must be blocked.

**Mechanic:** `canAttemptGeneralQuest` checks `player.questsAttemptedThisTurn < 2`. The turn label shows the count.

**Setup:** Any deck.

**Assertions:**
1. Turn label shows `0/2 quests used`
2. Attempt General Quest → attempt succeeds or fails → turn label shows `1/2 quests used`
3. Attempt General Quest again → turn label shows `2/2 quests used`
4. Click General Quest button a third time → button must be disabled OR an error modal appears with "quest limit" or "already used" text
5. MP before / after each quest attempt is recorded — confirm MP changed after each resolved quest
6. On the third attempt: MP must be unchanged (no partial deduction on a blocked attempt)

**File:** `tests/ui/mechanics.spec.js`
