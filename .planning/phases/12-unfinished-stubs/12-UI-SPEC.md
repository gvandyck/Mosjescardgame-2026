## Scope Note

## Typography

Source: `styles/main.css` CSS variables + `styles/board.css` modal classes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / modal paragraph | 14px (0.88–0.92rem) | 400 (Rajdhani regular) | 1.5 |
| Label / option name | 15px (0.95rem) | 400 (Rajdhani, `.mosje-select-name`) | 1.4 |
| Button | 11–12px (0.72rem) | 700 (Bebas Neue display, letter-spacing 0.08em) | n/a (fixed height 40px) |
| Modal heading (h3) | inherits Bebas Neue at ~18–20px | 400 (Bebas Neue is inherently heavy) | 1.2 |

Note: Bebas Neue weight 400 renders visually bold due to the typeface design. Do not override with `font-weight: 700` on headings — the existing rule `h1, h2, h3 { font-family: var(--font-display); font-weight: 400 }` is authoritative.

Note on 14px body / 15px label: these two sizes differ by 1px, which normally matches the anti-pattern. Both sizes are inherited from the existing `modalManager.js` pattern and cannot be changed without refactoring all existing modals. Hierarchy between body and label is distinguished by color (`#c8c8d0` body vs `#e0e0e0` label) per existing CSS, not by size alone. Do not adjust either value in Phase 12.

For all three Wave 4 modal overlays (STUB-11, STUB-14, STUB-15):

## Component Inventory

All three Wave 4 interactions use existing `modalManager.js` functions. No new functions are added.

### STUB-11: Bagga of Greed — Discard One of Two

**Trigger:** After drawing 2 cards via Bagga of Greed, if `_baggaDiscard === true` flag is detected in the UI handler.

**Function:** `showCardChoice(title, cards)`

**Exact call:**
```js
const cardToDiscard = await modal.showCardChoice(
  'Bagga of Greed — Discard a Card',
  drawnCards  // array of 2 card objects: [{ cardId, name, description }, { cardId, name, description }]
);
// cardToDiscard is the chosen card object, or null if cancelled
// Move cardToDiscard from hand to discard pile
```

**Rendered structure:** `.modal-card` containing `<h3>`, `<ul class="modal-card-list">` with 2 `.modal-card-option` buttons, plus a ghost "Keep Both Cards" button.

**State contract:**
- `drawnCards` must be exactly 2 card objects with `{ cardId, name, description }` fields populated.
- If `showCardChoice` resolves `null` (ghost button pressed), do not discard — leave both cards in hand (player keeps both).
- If a card object is returned, move it from hand array to discard array.

**Copy:**
- Title: "Bagga of Greed — Discard a Card"
- Implicit prompt (none — the list is self-explanatory)
- Ghost button label: "Keep Both Cards"

### STUB-14: Welloe Force — Damage Redirect Target

**Trigger:** After the Welloe Force Piecie resolves its card-discard step, open a target selector so the player chooses which Mosje to redirect the next incoming damage to.

**Function:** `showOptionSelect({ title, prompt, options, allowCancel })`

**Exact call:**
```js
const targetId = await modal.showOptionSelect({
  title: 'Welloe Force — Redirect Damage',
  prompt: 'Choose a Mosje to redirect the next incoming damage to.',
  options: activeMosjeSlots.map(slot => ({
    id: String(slot.slotIndex),
    label: slot.name,
    metaLabel: `${slot.mp} MP`,
  })),
  allowCancel: false,
});
// targetId is the slotIndex string of the chosen Mosje
// Store in state as _welloeForceTarget = Number(targetId)
```

**Rendered structure:** `.modal-card` containing `<h3>`, `<p>` prompt, `.modal-mosje-select-list` with `.modal-mosje-select-btn` items showing name + MP value. No cancel button (`allowCancel: false` — redirect must be assigned).

**State contract:**
- `activeMosjeSlots` is the array of Mosje slots currently in play for the active player.
- All slots are enabled (no `disabled` flag) — any Mosje can receive the redirect, including the casting Mosje.
- Resolves with a slot index string; parse with `Number()` before storing.
- Store result as `_welloeForceTarget` in state for the damage-redirect consumer to read.

**Copy:**
- Title: "Welloe Force — Redirect Damage"
- Prompt: "Choose a Mosje to redirect the next incoming damage to."

### STUB-15: MP Adjuster — Value Picker

**Trigger:** When MP Adjuster Piecie activates, instead of hardcoded `mp = 50`, open a picker.

**Function:** `showOptionSelect({ title, prompt, options, allowCancel })`

**Exact call:**
```js
const chosen = await modal.showOptionSelect({
  title: 'MP Adjuster',
  prompt: 'Choose the MP value to set.',
  options: [
    { id: '20',  label: '20 MP' },
    { id: '40',  label: '40 MP' },
    { id: '60',  label: '60 MP' },
    { id: '80',  label: '80 MP' },
    { id: '100', label: '100 MP' },
  ],
  allowCancel: false,
});
const mp = Number(chosen);  // 20 | 40 | 60 | 80 | 100
// Apply mp as the new MP value for the target Mosje
```

**Rendered structure:** `.modal-card` containing `<h3>`, `<p>` prompt, `.modal-mosje-select-list` with 5 `.modal-mosje-select-btn` items. No cancel (`allowCancel: false` — player must choose a value to play the card).

**State contract:**
- `chosen` will always be a non-null string because `allowCancel: false` and options list is non-empty.
- `Number(chosen)` is always a valid integer in {20, 40, 60, 80, 100}.
- The previously hardcoded `mp = 50` is replaced entirely; do not fall back to 50.

**Copy:**
- Title: "MP Adjuster"
- Prompt: "Choose the MP value to set."
- Option labels: "20 MP", "40 MP", "60 MP", "80 MP", "100 MP"
