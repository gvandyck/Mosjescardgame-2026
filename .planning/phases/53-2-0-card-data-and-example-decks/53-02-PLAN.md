  <action>
One exported function per file (data modules export one const):
- `findCardBlock.mjs` exports `findCardBlock(source, id)` -> `{ start, end, indent }` or null. Same boundary rule as patchCardSource. `indent` = the whitespace before `id:`, which is the card's property indent.
- `toJsLiteral.mjs` exports `toJsLiteral(value)`: a single-line JS literal. Strings via `JSON.stringify` (never manual quoting); numbers, booleans and null as they are; arrays as `[a, b]`; plain objects as `{ key: value }` with unquoted identifier keys. Throws on undefined, functions and non-identifier keys.
- `setBlockField.mjs` exports `setBlockField(block, indent, eol, key, value, comment)`:
  - If the block has a line that is exactly `<indent><key>:`, replace that whole line with `<indent><key>: <toJsLiteral(value)>,` plus ` // <comment>` when `comment` is given. Match the same indent only, so nested keys are never touched.
  - If that existing line's value does not end on the same line (the line doesn't end with `,` or with `,` + comment), throw with the id and key.
  - If the key is absent, insert the new line immediately before the `<indent>artPath:` line. Throw if there is no `artPath:` line.
  - Never add a key ending in `rarity` other than `rarity` itself.
- `patchCard.mjs` exports `patchCard(source, id, fields, comments = {})`: detects the line ending (`\r\n` if present, else `\n`), finds the block, applies `setBlockField` for each `[key, value]` of `fields` in insertion order, and returns the new source. Returns null when the id is not found.
- `foilMosjeIds.mjs`: export const `FOIL_MOSJE_IDS`, the 12 ids: mosje_gandoe_wizard, mosje_alyssa_fissa, mosje_gandoe_destroyer, mosje_ronald_chef, mosje_ming_natural, mosje_martin_historian, mosje_coert_tech, mosje_jeffrey_gambler, mosje_fps_west, mosje_chris_ddr, mosje_amplifier, mosje_coert_kastelein.
- `applyCardList.mjs` (CLI; if you export, export one function `applyCardList(type)` and call it when the file is run directly):
  - Arg `type` is one of `mosjes|piecies|snelle|quests|places`. A config map gives each type its data file (`src/data/mosjes.js`, `piecies.js`, `snellePiecies.js`, `quests.js`, `places.js`) and its builder module `./build<Type>Fields.mjs`, loaded with dynamic `import()` (Type = capitalised type, e.g. `buildMosjesFields.mjs`). Builders for the other types are created in plans 53-04/53-05; this file must not be edited again for them.
  - For each parsed row of that type: `id = CARD_ID_MAP[type][row.name]`; call the builder's named export `build<Type>Fields(row, id, parsed)`, which returns `{ fields, comments }`; then `patchCard`. Ids missing from the file are reported, not created.
  - Writes the file once, keeping its line ending, UTF-8 without BOM. Prints `patched N / missing [ids]`.
  - For type `mosjes` only: after the rows, also patch `{ foil: true }` onto every id in `FOIL_MOSJE_IDS` that is not a Card List row (the 2 parked Mosjes).
- `tests/data/obby2-patch-card.test.ts` uses a small inline CRLF fixture with two cards and checks that:
  - an existing single-line key is replaced in place, and a missing key is inserted before artPath;
  - CRLF is kept, and nested same-name keys (deeper indent) are left alone;
  - strings containing `"` and `\` round-trip via `JSON.stringify`;
  - applying the same patch twice gives identical output (idempotent);
  - a multi-line existing value throws, and an unknown id returns null.
  </action>
