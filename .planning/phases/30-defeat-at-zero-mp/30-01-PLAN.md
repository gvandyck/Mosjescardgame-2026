# Phase 30 — Plan 01: Defeat at 0 MP

## Goal
Make a Mosje die (sent to discard/Welloe pile) when a **damaging effect** would reduce its MP below 0 while at **Level 0**. Implements the existing canonical ruling at [phase0-rulings.md:118](../../../docs/phase0-rulings.md). Today the engine silently floors MP at 0 and Mosjes are effectively immortal except via the 80-MP Gandoe elimination and Call-of-Welloes anchor loss.

## The exact rule (confirmed with user)
When an effect reduces a Mosje's MP and the result would be **< 0**:
- **Level > 0** → regress one or more levels, carrying the overflow into the new level (the existing `while (mp < 0)` loop already does this — keep it).
- **Level 0** → the Mosje is **killed**: routed through `markMosjeDefeated` (discard pile and Welloe pile are treated as the same destination; existing shields/Not Today!/Call-of-Welloes cleanup still apply).
- **A Mosje never holds negative MP.** Floor remains 0 for survivors.

### What must NOT die
- A Mosje **summoned/placed at exactly 0 MP** (e.g. starter Mosjes with `startMP: 0`, Call of the Welloes summons). Nothing *reduced it below 0*, so it lives. This falls out naturally: placement never calls a reduction path.
- A Mosje **paying its own MP cost** (Youri −20, Gandoe −80, Coert −10, etc.). Abilities already gate on "enough MP" before paying, so a cost can't push below 0. Cost reductions must use a non-lethal path / source so the defeat sweep ignores them.

## Architecture decision: flag + centralized sweep
There are **4 independent MP-reduction sites**, and 3 of them (`applyDamage`) operate on a *bare mosje object* with no `state`/`playerId`/`slotIndex`, so they cannot call `markMosjeDefeated` themselves:

| File | Function | Has state? |
|------|----------|-----------|
| `src/engine/mpManager.js` | `loseMP(gameState, playerId, slotIndex, amount, source)` | ✅ yes |
| `src/abilities/piecieEffects.js` | `applyDamage(mosje, amount)` | ❌ bare mosje |
| `src/abilities/mosjeAbilities.js` | `applyDamage(mosje, amount)` | ❌ bare mosje |
| `src/abilities/placeEffects.js` | `applyDamage(mosje, amount)` | ❌ bare mosje |

**Solution:** the reduction sites set a marker on the mosje when level-0 overflow occurs; a single sweep consumes it.

1. In each reduction site, replace the `if (level === 0) { mp = 0; break; }` branch with:
   `if (level === 0) { mp = 0; mosje._pendingDefeat = true; break; }`
2. Add a sweep `applyPendingDefeats(state)` that scans every player's `activeSlots`, and for each slot with `_pendingDefeat`, calls `markMosjeDefeated(state, pid, idx)` (which clears the slot, routes to graveyard/Welloe, honors WELLOE_SHIELD + Not Today!, and re-checks victory).
3. Call `applyPendingDefeats` at the **top of `checkVictory`** — `checkVictory` is already invoked after every action across the engine, so this gives one centralized hook with no new call sites in the dozens of effect functions.

> Why `checkVictory`: it's the single post-action chokepoint already wired into `loseMP` callers, `activatePiecie`, `useMosjeAbility`, `resolveQuest`, `endTurn`, and bot steps. Sweeping there guarantees the defeat resolves immediately after any damaging effect, before KNOCKOUT is evaluated.

### Cost-payment safety
`loseMP` takes a `source` string. Cost payments must NOT trigger defeat. Two options — pick in Task 1:
- (a) Add a `COST` source and skip `_pendingDefeat` when `source === 'COST'`; migrate ability cost calls to use it.
- (b) Keep abilities deducting MP via direct `slot.mp -= cost` (most already do, e.g. Gandoe `gandoeSlot.mp -= 80`), which never sets the flag. Audit that no ability pays a cost through `loseMP`/`applyDamage`.

Preference: **(b)** — least churn. Verify in Task 1 that every MP cost is a direct subtraction guarded by an "enough MP" check, not a `loseMP`/`applyDamage` call.

## Success criteria
1. A Lv0 Mosje reduced below 0 by any damaging effect (quest fail, piecie, place, snelle, ability) is sent to graveyard/Welloe via `markMosjeDefeated`, and KNOCKOUT fires when it was the last Mosje.
2. No Mosje ever holds negative MP; Lv>0 Mosjes regress levels with overflow carry exactly as before.
3. Mosjes summoned/placed at 0 MP (starters, Call of the Welloes) are NOT killed on placement.
4. MP-cost payments never kill the paying Mosje.
5. `npm test` green (Ronald Kip stacking test included); `npm run typecheck:source` green.
6. Simulation crash-free, timeout < 25%; bot-vs-bot 30 games pass with no negative-MP anomalies.
7. `node --check` clean on UI files.

## Risk notes
- **Recursion**: `markMosjeDefeated` → `checkVictory` → `applyPendingDefeats`. Flags must be cleared to make re-entry a no-op.
- **Double-routing**: a slot already nulled by `markMosjeDefeated` must be skipped by the sweep (null check).
- **Balance**: KNOCKOUTs become common; this is intended (implements ruling) but will change win-rate data — re-baseline the simulation.
- **Hidden cost-via-loseMP**: if any ability pays a cost through `loseMP` (Task 1 audit), it must use the `COST` source or be converted to direct subtraction, else paying a cost could wrongly kill.
